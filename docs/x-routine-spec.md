## 0. 運転モード: リライト運転（v4.1・最重要）

- ルーティンの成果物は投稿ではなく**下書き**。`add_post` に **`status='draft'`** を渡す（pendingを積まない。自動投稿は走らない）
- **下書き本文はゲート1〜4（実名・数字・新情報・含意）だけ満たす。一人称（ゲート5）は本文に書かない** — 新田さんの声を機械が偽造しない。代わりに **`hint` に「解釈の種」を2〜3個**渡す（例:「元請の受注絞りと繋げる角度 / 下請けの工期交渉の話に落とす角度 / 自社の採用面から見る角度」。各15〜30字）
- 新田さんはSlackに届いた下書きを自分の言葉にリライトして投稿する。**枠時刻（7:25/12:00/20:00）は目安でズレてよい**
- AI臭ワード辞書・文ごと改行・字数・マンネリチェックは下書きにも従来通り適用する（リライトの土台が汚いと直す手間が増えるだけ）

### 休載の基準（v4.2改訂）

- **感情ゲート（§1のゲート0）を通るネタが見つからない時は休載する**。おもろくない下書きは新田さんのリライト時間を奪うだけ
- ただし休載判定の前に**最低5ネタ探索**し、危機直撃・暴露・通説反論の型に変換できないか粘る（「新情報が弱い」「マンネリ気味」だけの休載は引き続きNG）
- 休載時も絡みカード（§6）は書いてcommitする。commitメッセージは `skip: <枠> <理由>`

## 1. 投稿の必須要素ゲート（1つでも欠けたら没にして別ネタ・最大3回試行）

0. **感情ゲート（v4.2・最上位）**: 読者（下請け・工務店の社長）の感情が1個動くか。**やべえ**（危機が自分に来る）/ **マジか・そこ言う？**（暴露・意外）/ **いや違う**（通説反論）。どれが動くかを下書きを書く前に一言で言えないネタは、実名・数字が揃っていても没。書き始めるのは「ニュースに何が書いてあるか」ではなく「読者の仕事・金・工期に何が起きるか」（勝ち型4種は x-strategist.md 参照）
1. **実名1つ以上**（企業名 / 制度名 / 省庁名 / 統計名。出典が言える実データ）
2. **数字2〜4個**（%・円・件数・人数・日付。**上限4個・主役は1個**。2026-07-31追加: 数字の羅列は決算レポート調になって機械っぽさの主因。一番意外な数字を主役に立てて、残りは捨てる勇気を持つ）
3. **新情報1つ以上**（読者がブックマークか引用したくなる）
4. **現場への含意1行**（格言・標語ではなく具体で）
5. **一人称の一次観点 → v4.1では本文に書かず `hint`（解釈の種）で渡す**

### 下書きの文体（2026-07-31追加・「機械っぽい」対策）

下書きはリライトの土台。報告書ではなく「新田さんが話してる途中」の文を作る。x-strategist.md の参考文体（新田さん自身の投稿）に寄せる:
- **1行目は感情フック**（v4.2追加）: 機関名・統計名・「2025年度の〜は」で書き始めない。読者の損得か違和感で始める（✕「2025年度の住宅着工は71万戸」→ ◯「住宅の仕事、減ってるどころの話じゃなかった」）。出典（機関名＋発表日）は2行目以降で支える
- **ニュース原稿語尾を使わない**: 「〜と発表した」「〜となった」「〜が明らかになった」→「〜が出た」「〜って数字が出てる」「〜らしい」
- **文は短く**。1文で2つのことを言わない。話すリズム
- **数字は主役1個を立てる構成**にする（他の数字は主役を支える時だけ。並列に並べない）
- 地の文は話し言葉寄り（でも・だから・やっぱり OK）。専門用語は必要なら使ってよい
- 読者への呼びかけ1行はOK（「〜は見といたほうがいい」等。一人称の意見とは別物なのでゲート5違反にならない）

### ゲート5の扱い（v4.1: 人間側工程に移管）

- **下書き本文には「僕は〜と思う」等の一人称を書かない**。新田本人の判断・解釈はリライトで本人が注入する（機械が声を偽造した投稿は転換しない、が v3.2〜v4 の教訓）
- 代わりに `hint` に**解釈の種を2〜3個**（各15〜30字・「/」区切り）。事実から伸ばせる別々の角度を出す（例:「元請の受注絞りと繋げる / 下請けは工期交渉を先に / 採用単価の逆転現象と重ねる」）
- ✕ 創作した商談・訪問・会話をhintに入れる / ✕ コンサル一般論だけのhint
- エピソードバンクは本文・hintとも使用禁止（創作を含むため）

## 2. 自己リプは作らない（維持）

`add_post` に `reply_text` を**渡さない**。ソースURLリプ廃止。出典は本文内に「機関名＋発表日」で書く。URLは本文にもリプにも載せない（`source_url` はdashboard.jsonに残すだけ）。

## 3. マンネリチェック（維持）

過去14日の post_queue.json のオリジナル投稿（draft含む）を読んで、(1)同一の具体的数字×固有名詞ペアの再利用禁止（ジャンル自体は新事実が出れば毎週OK） (2)直近5投稿と同じ書き出し構文禁止 を守る。

## 4. ネタ収集（維持）

WebSearchで収集。優先ジャンル（v4.2・実績順）: **倒産・資金繰り / 業界の裏側・通説と違う実態 / 資材値上げ・供給停止 / 仕事量の増減（着工・受注・決算） / 労務単価・賃金・人手**。制度改正・審議会・とりまとめ公表は、読者の金・締切に直撃する時だけ（解説は没）。ネタを選んだら、勝ち型4種（x-strategist.md）のどれに変換するかを決めてから書く。

ニュースは72h以内優先、統計は発表6ヶ月以内のみ。**ファクトチェック必須**: 企業名・数字・制度名・日付はWebSearchで裏取りし、裏取り不能な要素は削るか没にする。

## 5. 土曜朝はフラッグシップ（v4新設・x-post-morningのみ）

土曜の朝枠は通常のA型ではなく**「今週の建設業、数字で3つ」**を書く:

- その週（月〜金）の統計・決算・制度ニュースから3つ選ぶ（各ネタは72h制限の例外。その週のものならOK）
- 構成: 導入1行 → 数字ごとに「1〜2行の事実」×3。300字級フル尺。総括の解釈は書かず `hint` に角度を渡す（v4.1: 新田さんがリライトで注入）
- 型（見出し行・番号の振り方）は毎週同じにする。看板として認知させる
- 各数字は本文中で「機関名＋発表日」を添える。ゲート・文体・マンネリチェックは通常通り
- 数字が3つ以上並ぶので表画像（`image_type='gemini'`）を付けてよい（迷ったら無し）

## 6. 絡みカード: 各枠3〜4枚・完成文形式（2026-07-31 新田さん要望で1日10枚目安に増枠）

**このカードの目的は新田さんがコピペ10秒で投稿を完了すること。** 全カード完成文で書く。

- **各ルーティンは3〜4枚**書く（1日合計10枚目安）。朝・昼=**リプ型**、夜=**リプ型＋引用RT型を最低1枚**（引用RTは相手の投稿に自分しか出せない数字・事実を1個足す。「同意です」だけの引用は没）
- **条件を満たす候補が足りない時は無理に埋めない**（質>数。化石投稿や業界外を混ぜるくらいなら2枚でいい）
- 3条件AND（機械検証必須）:
  1. **24時間以内の投稿**（snowflakeで検証・**6時間以内を優先**）
     ```bash
     python3 -c "print(__import__('datetime').datetime.fromtimestamp(((ID>>22)+1288834974657)/1000))"
     ```
  2. **建設業界に直接関連する内容**（業界外はどれだけバズってても除外）
  3. **いいね50以上 or 投稿者フォロワー2,000以上**
- 優先順: ①A tier（@karube_sanei @inatake0 @TKG_CraftBank @Stoneman_ISHIO @shinkojuki @carpentershoyan @monozukuritarou @sekokan_kun）の6h以内投稿 ②業界紙・記者（@kensetsunews @nikkenko 日経クロステック） ③tier外の建設関連バズ（min_faves 100+）
- 同日の他枠のカードと同じ投稿・同じ相手は選ばない（dashboard.jsonの他枠カードを確認）
- **draftは完成文**: そのまま投稿できる形で書く。やさしい口調60〜100字、データ補足型（自分しか出せない数字・事実を1個）優先、論理飛躍禁止、DM誘導禁止、自社宣伝禁止
- 条件を満たす候補が本当に無い枠は絡みカード無しでよい（無理に埋めない）

**書き込み先**: dashboard.json の `engage_cards` に**その枠の3〜4枚**（上書きOK）。`engage_pool_{枠}` にも同じものを書く（互換用）。`reply_sales` は書かない。
- engage_cards のフィールド: `no, action_type("reply"|"quote"), target_account, name, tier, target_post_url, target_snippet, engagement, text`（**textは完成文**。Slack通知はengage_cardsを読む）
